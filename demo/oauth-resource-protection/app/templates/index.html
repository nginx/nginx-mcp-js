MCP OAuth resource protection

NGINX Plus validates access tokens and permissions before calling a tool. It checks tool permissions, replaces caller identity with verified claims, and records its decisions in audit logs and traces. Requires an NGINX Plus commercial subscription.

What NGINX does: key configuration

NGINX is the OAuth resource-server boundary. It advertises resource metadata, challenges unauthenticated clients with HTTP 401, validates JWT signatures and time claims, and checks issuer, audience and token profile. Tool policy runs after authentication; missing scope returns HTTP 403.

location = /mcp {
    auth_jwt "MCP";
    auth_jwt_key_request /_jwks;
    auth_jwt_require $mcp_token_profile;

    internal_redirect @mcp_authenticated;
}

location @mcp_authenticated {
    if ($mcp_scope_allowed = 0) {
        return 403;
    }

    proxy_set_header Authorization "";
    proxy_set_header X-User $jwt_claim_sub;
    proxy_pass http://information;
}

Illustrative excerpt. The full configuration also checks MCP headers against the request body, sets Bearer challenges, and exports audit events and optional OpenTelemetry spans. The njs token-profile predicate runs only after JWT signature validation.

Documentation: auth_jwt, internal_redirect, MCP authorization.

What the demo environment does
  • Python is the OAuth client: web UI and CLI initiate the same scenarios, discover the IdP, exchange code + PKCE for tokens, and call MCP.
  • Keycloak performs browser login and consent, issues tokens and publishes signing keys. Login uses the demo account alice / alice.
  • The MCP backend executes allowed tools and confirms the identity headers received from NGINX.
  • Collector, Loki, Tempo and Grafana expose audit decisions and the edge/backend/tool trace. Use the result links to inspect one request.

Clear removes application tokens only; Log out from IdP also ends browser SSO. Previously issued JWTs may remain valid until expiry.
